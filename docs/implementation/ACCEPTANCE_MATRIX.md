# Complete-specification traceability

Source: `docs/Grassroot_Project_Architecture.md` (unchanged). Rows enumerate all specification
headings, bullet requirements and table rows with source line numbers. Subordinate prose is
covered by its containing section. User decisions supersede provisional source examples:
XIAO GPIO1/2/3/4/5/6/43/44 with SLP tied to 3V3; joystick pins await wiring; turns are in-place;
robot uses existing Wi-Fi, controller uses USB serial, local OCR and Nano Banana artwork.

**Implemented software is not physical acceptance.** All electrical, actual robot, joystick,
camera placement, optical projection, real-card OCR benchmark, real-user learning validation,
and live paid image-provider checks remain pending. No sample can substitute for these.

Known software limits: open-loop discrete motion needs measured calibration; continuous replay
is approximate; BKT is an illustrative estimator with explicit uncertainty; OCR requires manual
review and has not been tuned against actual cards. Native camera reads can delay teardown;
STOP bypasses acquisition. Continuous input has a bounded buffer and stops at its duration limit.
Duplicate IDs are retained without eviction for up to 128 accepted discrete commands per
powered session. A full ledger rejects further motion until a stopped power cycle; it never
re-executes an old ID. A power cycle clears history; the backend never retries an interrupted run.
